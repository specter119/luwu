# M2: Resource and semantic drift foundation

Status: implemented in the current working tree; closure is pending the repository's packaging and hook gates.

M2 proves that Luwu can observe multiple declared resources and run an explicitly selected semantic comparison without claiming a write contract that has not been defined.

## Scope

- manifest version 2 with multiple resources ordered by name;
- explicit literal `copy` resource observation in addition to the M1 kinds;
- deterministic cross-resource target/source conflict and path-overlap validation;
- complete multi-resource `inspect` and `plan` observations;
- explicit `exact-bytes` and strict `json` comparison strategies;
- resource-level blocked observations and metadata-only comparison results;
- version 2 apply refusal before any write.

M2 does not include baselines, field ownership, reverse sync, providers, secrets, multi-resource apply, rollback, or durable plans. Those remain M3/M4 work.

## Exit checklist

- [x] M1 version 1 manifest and single-resource apply behavior remain covered by regression tests.
- [x] Version 2 validates all resources in deterministic order and rejects ambiguous paths.
- [x] A plan observes all resources even when one resource cannot render safely.
- [x] Strict JSON rejects duplicate keys, invalid syntax, invalid UTF-8, and non-finite numbers.
- [x] Strict JSON rejects excessive nesting and isolated Unicode surrogates.
- [x] JSON semantic drift is reported, not silently replaced; formatting-only equivalence is a no-op.
- [x] Version 2 apply returns `m2_read_only` before target writes.
- [x] Human and JSON output identify comparison and read-only capability without configuration content.
- [x] Equal finite JSON numeric spellings have an explicit, tested equivalence rule; booleans remain distinct from numbers.
- [x] `uv build` produces the source distribution and wheel with its required dependency access.
- [ ] `prek run --all-files` passes with a writable repository checkout and hook cache.
