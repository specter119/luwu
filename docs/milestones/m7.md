## Production patcher ablation — 2026-10-14

Run from the repository root with:

```text
UV_CACHE_DIR=/tmp/luwu-m7-uv-cache uv run --script experiments/m7_ablation.py
```

The experiment calls the checkout's production `patch_m6_document` directly.
For updates and deletion, it compares the returned bytes with independently
written expected byte strings and checks the result with both `tomllib` and
the product parser. It also contrasts the prior comment-rejecting scalar
check, naive `#` splitting, and whole-document reserialization, and retains
negative controls for the unsupported TOML shapes. It is a focused design
ablation, not a substitute for the implementation, CLI, or main-session
gates.

Run result: passed on 2026-10-14 with the production patcher. Four scalar
update cases matched independent expected bytes and both TOML parsers;
whole-line deletion matched its independent byte expectation; and all five
unsupported-syntax controls were rejected.
The naive `#` split broke all three quoted-string cases, while whole-document
serialization preserved TOML semantics but lost comments and byte layout.
For this bounded syntax, the existing production span patcher met both byte
preservation and semantic checks without an AST or adapter framework.

The initial read-only interface comparison recorded implementation gaps that
have since changed. The following correction status is based on the current
source modules and tests; the final release evidence is recorded below.

**Corrections now present in source:**

- Copy baselines now store the digest algorithm (`sha256`) with the accepted
  public digest and store accepted mode separately. This remains explicit
  public baseline content evidence. The [reference](../reference.md#m7-full-dotfiles-coverage-manifest-version-8)
  defines that the digest is not emitted in results, previews, repr, or logs.

- Durable baseline identity now records each resolved root path without its
  device/inode pair. Root device/inode identities remain execution-freshness
  checks. The current engine test asserts that root identity contains only the
  path.

- Directory expansion snapshots now include leaf identity. The manifest test
  replaces a leaf with a different inode but identical bytes and confirms that

- Resource plan projections now include `effective_mode`; the engine tests
  cover explicit, default, observed, and unavailable modes. The exact output
  contract is in [reference](../reference.md#m7-full-dotfiles-coverage-manifest-version-8).

- The engine now uses `m7_reverse_consumer_change` for the declared-consumer
  reverse-sync block. Undeclared resource drift has an actionable reason and
  uses the existing `m7_review_required` code. Their public meanings are in
  [reference](../reference.md#m7-full-dotfiles-coverage-manifest-version-8).

- Reverse destinations require an existing filesystem parent. The manifest
  test `test_reverse_destination_requires_an_existing_parent` expects
  `m7_path_missing`; the old mismatch report is resolved.

- The schema-2 baseline and input decoding boundary received a final focused

## Plan-evidence authorization decision and candidate history — 2026-10-14

The main session accepted two clarifications after adversarial review. First,
equal plan graphs may differ in internal alias topology: splitting one shared
subnode into equal copies or merging equal copies is not, by itself, an
authorization change. The required comparison still covers every projected
edge and value, exact scalar type, Decimal representation, parser span, and
source bytes; a changed value or span remains a mismatch. Astra withdrew the
earlier proposal to require alias-topology equality after the main session
challenged its security basis. This supersedes that earlier review assumption;
it is not a newly discovered write-safety defect.

Second, the approved mutation flow fully validates the caller plan at entry,
then verifies the manifest, freshly observes the selected profile, verifies
the manifest again, and matches that complete fresh projection against the
issued immutable evidence. Derived execution documents, inputs, observations,
baselines, ownership, and write bytes then come from the reauthorized state,
not from the original caller-derived plan objects. Mutating those original
derived objects later neither changes the authorized write nor acts as a
cancellation API. Shared declaration objects remain protected by the
independent registry check at each action, and the full per-action dependency,
callback, shared-consumer, own-write, final-no-op, and partial-outcome checks
remain in force. The main session approved removing the three retained origin
references and the repeated origin-graph check after authorization; that
change is now present in the engine. Astra's final diff review passed (session
`0c8`, history `5142`). The
[reference contract](../reference.md#m7-full-dotfiles-coverage-manifest-version-8)
and [design mechanism](../design.md#version-8-full-coverage-mechanism)
own the stable behavior and implementation explanation.

`m7_plan_evidence` is integrated, and the current engine no longer retains
caller-origin references or repeats the origin-graph check. The earlier
`source-final.json`, `wheel-final.json`, and `sdist-final.json` candidates each
reported 645 passing tests, zero errors, and zero skips. They preceded the
final type-probe allocation cleanup and are superseded by the release reports
below. These candidate names and results are retained as history, not as the
current release evidence.

The earlier installed 200-resource all-changed candidate measured a warm
median of 19.9868 seconds and failed the 10-second budget in
`.venv/m7-full-validation/benchmark-evidence-snapshot200.json`. A separate
in-memory removal-only origin-guard diagnostic took 4.8012 seconds for 200
resources and passed its independent oracle in
`.venv/m7-full-validation/origin-guard-ablation.json`. The latter is not an
installed-artifact run or final budget evidence. The final installed
